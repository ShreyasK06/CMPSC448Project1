TRAIN generations: fraction containing a newline and mean newline count:

Finding: the suspected mismatch does NOT occur. `baselines.build_texts` calls `src.preprocess.tokenize` first, which maps newline / CRLF to the literal token `<NL>` and joins tokens with single spaces; `str.split` then splits only on those spaces, so `<NL>` is a TF-IDF feature exactly as in the neural path (checked on 200 newline-containing generations: 200 contain `<NL>` in the TF-IDF input). Both paths see the same token stream (same 64/256 truncation, case kept). Remaining differences: TF-IDF uses word 1-2grams, min_df=2, 200k features; the neural vocab is unigram, min_freq=2, 30k cap. In the +char variant, `char_wb` 2-5grams run over the space-joined token string, so `<NL>` appears as the characters `<NL>`.

## TF-IDF prediction re-fit (T1)

`python -m src.analysis.tfidf_preds` re-fits word 1-2gram TF-IDF+LR (and +char) with C chosen on VAL macro-F1 and saves `runs/tfidf_{char_}{variant}_base.npz` (keys `test_y/pred/prob/source_id` as in the neural npz, plus `val_*`). Resulting [TEST split: test] numbers match `results.md` exactly: output 75.75 / macro-F1 75.48 (C=100), both 76.71 / 76.47 (C=10), char output 74.54 / 74.30 (C=10), char both 74.42 / 74.20 (C=10).

Reproducibility note: a first run with default multi-threaded BLAS did NOT match (output 75.88, both 76.92, char output 74.33). Cause: float32 lbfgs fits at C>=10 are sensitive to BLAS summation order (val acc at C=10, output: 75.38 multi-thread vs 75.04 single-thread; the original `Parallel` loky workers use 1 BLAS thread). The script now pins BLAS to 1 thread, which reproduces the stored numbers exactly. TF-IDF results therefore carry ~0.1-0.4 pt numerical jitter depending on thread count, comparable to the C-selection noise on val.

## Interpretation of T4-T7 (written after running the modules above)

All numbers are copied from the sections above; split labels as in those tables.

**Is attribution just length / format? (T5, T6).** Mostly no, but length and layout carry a substantial share.
- [TEST split: test] Length-only LR gets 37.71% (chance 20%); length-only HGB (same 4 features, non-linear) gets 51.88%; the 22-feature
  stylometry model gets 53.50% (LR) and 65.25% (HGB) against TF-IDF 75.75% and CNN ensemble 71.83%. The best shallow model is 10.5 points
  below TF-IDF, i.e. just outside the "within ~10 points" rule, so the honest reading is: roughly 85% of TF-IDF's accuracy is reachable
  from 22 hand-built length/format/punctuation statistics, and the remaining ~10 points need lexical information. We do not claim
  attribution is "largely" length/format, nor that it is independent of it.
- Length-matched test subset (820 rows, identical per-class length histograms): length-only HGB drops 51.9 -> 39.4 and stylometry HGB 65.3 -> 60.2,
  while TF-IDF drops only 75.8 -> 74.4 (CNN 71.8 -> 70.4, BiLSTM 69.4 -> 67.9). Length explains a large part of the shallow models'
  accuracy but little of TF-IDF's.
- Quintiles: TF-IDF is 72-80% in every raw-length quintile; the stylometry HGB is 57.5% in the shortest quintile but 81.4% in the longest
  (where class mix is chatgpt 44%, mpt 1%, so length alone is very informative). Models are more accurate on outputs at the 256-token cap
  than below it (TF-IDF 77.9 vs 73.3), consistent with more text = more evidence.
- T6: TF-IDF accuracy rises monotonically with the number of tokens kept (K=32: 55.46, 64: 59.71, 128: 69.83, 256: 75.75, full: 78.67; all
  Holm-significant vs K=256). Collapsing format (no <NL>, markdown stripped): 76.21 (p=0.44), lowercasing: 75.62, masking self-identification
  phrases: 75.96 - none is distinguishable from the base (Holm p=1). So the TF-IDF result does not hinge on newline/markdown tokens, casing
  or boilerplate; the 256-token cap is the single biggest handicap (full text +2.9 points). Caveat: `full` hits the 200k max_features cap.

**Where the errors are (T4).** Model confusion is concentrated in mistral-chat <-> mpt-chat (121 of the 582 TF-IDF errors; 146 for the CNN)
then llama/mistral and cohere/mistral. chatgpt, cohere-chat and llama-chat are recalled at 79-88% by TF-IDF, mistral-chat and mpt-chat at 61% and 66%.
TF-IDF and the CNN ensemble agree on 253 of the 398 rows both miss, so the errors are largely shared (hard rows), not model noise.
The mean-prob ensemble at a pre-specified w=0.5 gives 77.46% (secondary; the neural runs saved no VAL probabilities so no VAL-tuned weight was possible).
Top n-grams: only about 1-9 of each class's 30 top features are formatting/boilerplate (cohere "Here is", llama "Sure", "Here's", `<NL> *`),
most are content words or sentence-opening punctuation patterns (". Experimental", "Overall ,"), which is partly domain-specific vocabulary
(each model's phrasing in a given domain), not only style. The heuristic tagger is crude (see its definition).

**Domain gap (T4).** The brief said recipes/reviews ~85% vs news/poetry ~55%; the actual TF-IDF TEST accuracies are reviews 89.3, recipes 88.0,
news 62.4, wiki 68.6, reddit 71.4, poetry 74.2 (poetry is higher than the brief). Domains with high accuracy are where the five models differ most
in surface form (reviews: per-class mean length 136-367 words and 33-100% have a newline; recipes: heavy structure, 27 newlines per output);
news and wiki are where all five models write long, similarly-formatted prose (news per-class length 192-353, 87-100% with newline; ~70-83%
of outputs hit the cap so the content that distinguishes models is truncated). The length/format-only stylometry model does not explain the gap
cleanly (it is 65.0% on news, higher than its 60.7% on abstracts), so the gap is not just length/format: it is also lexical distinctiveness of
the model's phrasing by domain. Treat this as a correlational explanation.

**RQ3 (T7).** [TEST split: test_code] Every text-trained model scores ~20% (TF-IDF 19.55, CNN ens 19.70, BiLSTM ens 20.10) = chance, and all of them
collapse to cohere-chat (95.5-99.3% of predictions). Code outputs are far outside the text distribution: 28-37 words on average, 1-2% hit the cap
(text: 27-87%), no markdown fences, 13.9% of tokens are OOV for the text vocabulary versus 2.9% for held-out text. A stylometry model sees
the same collapse (93.8% cohere), so the length/format shift alone sends code to the class with the shortest, least-structured text outputs
(an inference, not tested separately). The ceiling shows code is attributable in principle but harder: TF-IDF trained and cross-validated on code only
reaches 49.40 +/- 2.27 accuracy (grouped 5-fold, 400 ids; chance 20, text CV 76.24 +/- 0.56) using only 320 training ids per fold. So the text-to-code
failure is mainly domain shift (a classifier with the right in-domain data gets ~2.5x chance); but code is also intrinsically less
attributable than text (short, near-identical solutions across models), and the ceiling is a lower bound for what a better code model might reach.
