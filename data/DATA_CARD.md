# Data card: RAID chat-model subset (CMPSC448 Project)

Generated by `python -m src.data` (deterministic, seed 42). Detailed tables: `reports/coverage/coverage.md`,
`reports/data_checks.md`, `reports/prompt_analysis.md`.

## Source and license
- Dataset: `liamdugan/raid` (RAID), `raid` config, **train** split (labeled). `raid_test` is unlabeled and is not used.
- Code domain: RAID `extra` split (domain == `code`).
- License: MIT.

## Access method
The HF parquet mirror was partial and the CSVs are grouped (sorted by model/attack), so a prefix or random-row read
is biased. We streamed the entire train.csv (11.8 GB) and extra.csv (3.7 GB) over HTTP (resumable Range reads),
filtering on the fly with `src/raid_stream.py`:
`python -m src.raid_stream --url <csv url> --out data/interim/x.parquet --counts data/interim/c.csv`
Outputs: `data/interim/train_chat_none.parquet` (213,936 rows), `extra_code_chat_none.parquet` (14,720 rows), and
count tables over ALL rows (`train_counts.csv`, `extra_counts.csv`).

## Filters
attack == `none`; non-human; models chatgpt, cohere-chat, llama-chat, mistral-chat, mpt-chat (one chat model per
family); decoding == `sampling` and repetition_penalty == `no`; non-empty generation.
Labels: chatgpt=0, cohere-chat=1, llama-chat=2, mistral-chat=3, mpt-chat=4.

## Coverage findings and decoding choice
- Every model name (including human) has identical row counts per domain: 13,371 source_ids in the 8 text domains
  (abstracts 1766, books 1781, news 1780, poetry 1771, recipes 1772, reddit 1779, reviews 943, wiki 1779) and 920 in code.
- chatgpt and cohere-chat have ONLY repetition_penalty `no` (no `yes` rows), so `no` is the only value every
  chosen model covers. (gpt3, gpt4, cohere are also `no`-only; gpt2, llama-chat, mistral, mistral-chat, mpt,
  mpt-chat also have `yes`.)
- Both greedy and sampling are fully covered for all 5 models in all domains. We chose **sampling**: greedy
  outputs of open models are prone to degenerate repetition loops, an easy shortcut that is less representative of
  realistic use.
- Human text is in the counts but is not part of this model-attribution dataset.

## Sampling design
Paired by source_id. For each text domain, candidates are source_ids with exactly one (sampling, no) row for each of
the 5 models (no duplicate (source_id, model) pairs were found; asserted). Candidates are sorted, then
`rng = np.random.default_rng(42)` draws N=400 per domain (one shared rng, domains in the order abstracts, books,
news, poetry, recipes, reddit, reviews, wiki). All 5 generations of each chosen id are kept:
400 x 5 = 2,000 rows/domain, 16,000 rows, 3,200 per model, 400 per (model, domain). Code: 400 ids from 920 with a
fresh `default_rng(42)` (2,000 rows), kept aside for RQ3.

## Splits
- Main: 70/15/15 by source_id over the text df (ids sorted, shuffled with `default_rng(42)`):
  train 2,240 ids / 11,200 rows, val 480 / 2,400, test 480 / 2,400. All 5 generations of an id stay in one split,
  so classes are exactly balanced per split. Saved to `data/processed/raid_main.parquet`.
- RQ3 (`data/processed/raid_rq3.parquet`): text rows with split_rq3 train / val / test_indomain (from train / val /
  test) plus 2,000 code rows with split_rq3 = `test_code` (and `split` = `test_code`). Code source_ids are disjoint
  from text source_ids (asserted).

## Prompt analysis (matters for RQ2 "prompt only")
- The `prompt` is identical across the 5 models for 3,200 / 3,200 source_ids (100%) in text and 400 / 400 in code.
  The prompt is a deterministic function of (domain, title).
- Distinct templates (title replaced by `<TITLE>`): 1 per domain, 8 per model overall (1 for code); the title is found
  verbatim in the prompt for 100% of rows. Example: `Write the abstract for the academic paper titled "<TITLE>".`
- Consequently a prompt-only classifier has no information about the generating model: it should be at chance
  (~20% for 5 classes). That is an expected, meaningful RQ2 result, not a bug.

## Known limitations
- Sampling-only, repetition_penalty `no`-only: no greedy / rep-penalty variation; results may not transfer to them.
- Only attack == none (no adversarial robustness); only 5 chat models, one per family; no human class here.
- RAID chat prompts are fixed one-line templates around a title; every model sees the same prompt, so prompt-only is
  uninformative by construction.
- reviews has only 943 source_ids (still >= 400); text length and style differ by domain.
- N=400 ids/domain is a subsample of ~1,800 (reviews 943); the subsample is fixed by seed 42.
- Code is a single domain with short snippets, so RQ3 code transfer also shifts the length distribution.
